# Независимая проверка качества

Эксперимент V3 проверяет, поможет ли больше человеческих примеров Weather
лучше распознавать обсуждения не по теме. Ученик сохраняет NLI-предобученную
базу ModernBERT-large, шесть выходов A–F и LoRA-r8: 398 269 452 параметра,
из них обучаются 2 432 006. Формат входа, функция обучения и решение
«релевантно, если P(F) < 0,5» остаются прежними. По DEV выбрана вторая эпоха C
(C2) с описанным ниже компромиссом. Новый FINAL оценивается впервые;
его метрики пока ожидаются.

До обучения зафиксирована смесь из 23 561 примера: 8023 HN с silver-разметкой
учителя, 6322 человеческих NewsMTSC, 8192 Weather и 1024 Airline.
Weather TRAIN содержит по 2048 уникальных примеров каждого из четырёх
классов по однозначному определённому победителю человеческих голосов.
При обучении сохраняются исходные мягкие распределения голосов и веса
определённости; этот отбор не превращает их в жёсткие метки.

Первоначально до обучения заданы два рецепта. A обучается с нуля две эпохи:
learning rate 0,0003 для LoRA и 0,001 для головы. Если ни одна эпоха A
не проходит все ограничения, запускается заранее заданный B на той же смеси:
две эпохи с learning rate 0,0001 и 0,0003 соответственно. A и B не прошли
ограничения DEV.

После оценки A/B добавлена одна мотивированная проверка C. Это адаптивное
решение по DEV, а не третий заранее зарегистрированный рецепт. C обучается
с нуля две эпохи на той же смеси: LoRA — 0,0001, новый classifier — 0,0003,
предобученная NLI-проекция `head.dense`/`head.norm` — 0,00003. Гипотеза:
меньшая скорость изменения предобученной проекции поможет сохранить полезные
признаки при обучении нового выхода. Раздельные скорости обучения описаны
в [discriminative fine-tuning](https://aclanthology.org/P18-1031.pdf).
Результаты выбора по DEV не доказывают перенос на новый FINAL.

Во время обучения C состав данных, soft-метки, веса примеров, функция
обучения и проверяемые исходные ограничения сохранены. DEV прежние:
Weather 1000, NewsMTSC RW 270, Airline 300, прежний Weather 198
и HN silver holdout 1977.

В исходном строгом протоколе precision класса F на Weather должен быть не ниже 0,70,
recall — не ниже 0,65. Macro-F1 полярности Weather и прежнего Weather
может снизиться относительно V2 максимум на 0,03; News, Airline и HN —
максимум на 0,02. Для HN отдельно ограничено снижение macro-F1 релевантности
на 0,02. Среди допустимых эпох выбирается максимальный взвешенный результат:
50% совместного macro-F1 четырёх классов Weather, 20% F1 класса F,
10% macro-F1 полярности Weather, 10% полярности News и 10% полярности Airline.
При равенстве выбирается более ранняя эпоха. HN holdout служит проверкой
сохранения согласия с учителем, а не независимой человеческой accuracy.

По DEV C2 не проходит один исходный гейт: macro-F1 полярности прежнего
Weather снизился с 0,85085 до 0,78331, то есть на 0,06753 при допуске 0,03.
Этот провал сохранён в исходном selection и не объявляется прохождением
всех первоначальных ограничений.

После сравнения DEV отдельно принято адаптивное решение
`primary-relevance-priority-v1`: C2 — единственный проверенный кандидат,
проходящий основные ограничения нового Weather/F, News, Airline и HN.
При продвижении выбран приоритет релевантности, а провал прежнего Weather
принят как явный компромисс и остаётся в отчёте. Это изменение приоритетов
после просмотра DEV, а не заранее зарегистрированный успех строгого протокола.
На новом Weather DEV у C2 precision F 0,7664, recall F 0,7480,
macro-F1 полярности 0,8490 и совместный macro-F1 0,79946.
Все эти числа относятся к DEV, использованному при выборе, а не к FINAL.

Прежние TEST и FINAL V2 уже просмотрены и остаются повторной диагностикой;
их тексты исключены из нового TRAIN. Для V3 до обучения отложен новый FINAL
из 1000 текстов Weather, по 250 на класс. Из него исключены все группы
прежних обучающих и проверочных примеров. Решение о продвижении C2, ID,
версия и SHA артефакта зафиксированы до первого открытия нового FINAL.
Его оценка выполняется; после неё настройки выбранной модели не меняются.
Метрики нового FINAL V3 пока не заявлены.

Из корня проекта:

```bash
python demo/quality/main.py --config demo/quality/config.yaml
```

У запуска только один аргумент — YAML-конфиг. Сначала `operation: prepare` скачивает закрепленные версии исходных данных и сохраняет SHA-256, происхождение, лицензии и разбиения в `manifest.json`. Затем `operation: evaluate_teacher` оценивает модель из `teacher_config`. Пути относительно корня проекта; данные, кеш ответов и результаты по умолчанию находятся в игнорируемой `.local-data/quality/`.

`operation: evaluate_student` оценивает уже обученного ученика из `student.registry_path`, не запуская обучение или учителя. Если `model_id` и `version` равны `null`, выбирается последняя обученная версия encoder для `student.entity`. Можно указать ID и версию явно. Отсутствующий registry считается ошибкой: пустая база не создаётся. Целостность артефакта проверяется штатным Registry. `student.device` и `student.cache_dir` позволяют использовать другое устройство и локальный кеш весов; при `null` сохраняются параметры артефакта. В примере указан кеш нативного демо 10k.

| Набор | Что проверяет | Разбиение после исключения утечек |
|---|---|---|
| NewsMTSC RW | Тональность к указанному упоминанию в политических новостях | 6322 train / 270 dev / 803 test |
| NewsMTSC MT | Тональность при нескольких целях в предложении | Тот же train / 320 dev / 1034 test |
| Weather Sentiment, прежний | Тональность и релевантность теме погоды, включая реальные off-topic | 198 dev / 792 test; эти тексты не используются для обучения |
| Weather Adaptation V3 | Обучение на погодных обсуждениях и проверка четырёх классов | 8192 train / прежние 1000 dev / новые 1000 final; оценка final после фиксации модели, разные группы текстов |
| Airline Sentiment | Отношение к авиакомпании в комментариях без размеченных границ цели | 1024 train / 300 dev / 1000 test; разные группы авторов, текстов и ID твитов |

[NewsMTSC](https://huggingface.co/datasets/fhamborg/news_sentiment_newsmtsc) размечен людьми, лицензия MIT. Исходные test сохранены; из train/dev исключены пересечения текста и групп источников с test. Для AllSides используется консервативная группа по общему числовому блоку исходного ID. RW и MT пересекаются между собой, поэтому их результаты считаются отдельно.

[Weather Sentiment](https://github.com/snorkel-team/snorkel/tree/f958365e4d8aa13a926a7e3a4505cff13f3bbeed/tutorials/crowdsourcing) взят из исследовательского архива Snorkel: исходные человеческие оценки и отдельная проверка их правильности. Исключены 8 неподтвержденных и 2 неопределенных ответа. Разбиение dev/test детерминированное, по человеческим классам. Лицензия исходных данных не подтверждена по сохранившемуся первичному источнику; данные скачиваются только в локальный кеш и не включены в репозиторий. Apache-2.0 репозитория-зеркала не объявляется лицензией твитов.

Новые Weather train/dev/final взяты из полного человеческого набора
[Partly Sunny with a Chance of Hashtags](https://www.kaggle.com/c/crowdflower-weather-twitter/data),
с закреплённым [CSV-зеркалом](https://raw.githubusercontent.com/sjoelee/twitter-weather/29466f8d9c60d5153debd37a6fbae2c8ed92f821/train.csv).
В нём S1 означает неопределённость, S2 — отрицательное отношение, S3 —
нейтральное, S4 — положительное, S5 — не по теме. Для обучения S2–S5
нормализуются в распределение четырёх классов A+B, C, D+E, F, а доля
определённых ответов уменьшает вес неопределённых примеров. Для V3 отобраны
8192 уникальных примера с однозначным определённым победителем: по 2048
отрицательных, нейтральных, положительных и не по теме. Случаи с максимумом
S1 или ничьей не входят в эту сбалансированную выборку. В выбранных примерах
сохраняются мягкие голоса всех классов, включая долю S1; вес равен
1 − нормализованная S1. Различие сильной и слабой интенсивности не
выдумывается. Используется прежняя функция обучения по четырём группам
классов; правила предсказания V3 не меняются.

Из полного набора исключены все 1000 исходных текстов прежнего Weather,
а также пересечения с другими используемыми корпусами. Исключение учитывает
точные и близкие повторы; train/dev/final разделены по группам текстов.
В TRAIN V3 также не входят просмотренный FINAL V2 и все прежние проверочные
группы. Новый FINAL V3 исключает все прежние обучающие и проверочные группы.
В источнике нет авторов и настоящих Twitter ID, поэтому независимость по
авторам не заявляется. В неизменном DEV и новом FINAL по 250 примеров каждого
из четырёх классов; случаи с максимумом S1 и ничьи оценок исключены.
Это сбалансированная диагностика, а не естественная частота классов.
URL, SHA и выбранные ID/группы закреплены в
[training_sources.yaml](../training_sources.yaml) и
[weather_benchmark.yaml](weather_benchmark.yaml). Разрешение на распространение
исходных твитов не подтверждено: CSV, тексты и производные разметки остаются
только в локальном кеше, вне Git.

[Airline Sentiment](https://huggingface.co/datasets/osanseviero/twitter-airline-sentiment) — исходная человеческая разметка CrowdFlower. Закреплённая карточка Hugging Face указывает CC-BY-NC-SA-4.0; CSV и производные наборы остаются только в локальном кеше. Целиком исключена группа `Delta`: 2218 из её 2222 текстов обращаются к `@JetBlue`, поэтому исходная цель ненадёжна. Остальные цели и метки не исправляются моделью; низкая уверенность аннотаторов не служит фильтром. Удалены точные повторы аннотаций. Связанные авторы, скопированные тексты и ID твитов сохраняются в одном разбиении. Dev содержит по 100 примеров каждого класса, test — 334 отрицательных, 333 нейтральных и 333 положительных. Это сбалансированная диагностика, а не частоты настроений всей аудитории. Все примеры относятся к авиакомпании: класс F здесь не проверяется.

1024 обучающих Airline выбраны фиксированным хешем из оставшихся 9034
примеров. Все компоненты авторов, текстов и ID, связанные с прежними DEV/TEST,
исключены целиком. Модель получает исходную цель и человеческую полярность;
учитель не переразмечает эти данные.

`datasets` выбирает наборы, `split: dev` используется для выбора модели. Переключайте на `test` после фиксации модели и промпта. `mark_target: true` обозначает предоставленный аннотаторами span как `[TARGET]...[/TARGET]`; позиции и метки не угадываются. Модель получает только сущность и текстовый контекст, без gold, split и оценок аннотаторов. Кеш учитывает ревизию учителя, протокол и полный вход.

Для восстановления новых Weather DEV/FINAL задайте в копии YAML:

```yaml
operation: prepare
data_dir: .local-data/quality/benchmarks
datasets: [weather_adaptation]
weather_benchmark: demo/quality/weather_benchmark.yaml
```

После подготовки `operation: evaluate_student`, `datasets: [weather_adaptation]`
и `split: dev` оценивают DEV. `split: test` оценивает отложенный FINAL;
для V3 этот запуск разрешён только после выбора модели и фиксации артефакта.
В той же копии задайте `student.registry_path`, `model_id` и `version`
нужного артефакта. Его обучение эта команда не запускает.

Для ученика ревизия кеша содержит SHA сохранённого артефакта, а протокол — SHA фактических `student.py`, `neural.py`, `supervision.py`, версии библиотек, формат входа, правило решения и выбранное устройство. Изменение кода или `mark_target` требует новых ответов. На Airline и Weather размеченных span нет; ничего дополнительно не ищется в тексте. Для проверки сценария мониторинга используйте также `mark_target: false` на NewsMTSC.

В результатах: accuracy и macro-F1 тональности, precision/recall/F1 релевантности, совместная матрица ошибок и 95% интервалы с повторной выборкой групп источников. Отказ F для релевантного примера считается ошибкой тональности. Совместный macro-F1 по четырем классам помечается неприменимым, когда в gold нет всех классов; например, NewsMTSC не содержит off-topic. Время учитывает только новые вызовы модели; кешированные ответы исключены.

Первая новая оценка включает ленивую загрузку модели; это явно отмечается в `timing` и для учителя, и для ученика. Замер callback не заменяет отдельный тест скорости. Все показатели качества здесь сравниваются с человеческими метками, а не с ответами учителя.

Эти наборы проверяют человеческую разметку, но не измеряют напрямую качество на Hacker News, ответы с контекстом треда или пять уровней интенсивности. Поля метрик интенсивности остаются пустыми. Возможное присутствие старых публичных benchmarks в предобучении LLM неизвестно. Совпадение ученика с учителем — отдельная метрика дистилляции, не независимая accuracy.

`operation: label_demo` размечает все 10 000 комментариев из `snapshot_path` выбранным учителем, без фильтров по упоминанию. `entity` и `aliases`, если равны `null`, берутся из конфигурации мониторинга. Сохраняются настоящие шесть вероятностей учителя, argmax-метка и проверяемое происхождение; это silver-разметка для обучения и демонстрации, не человеческий эталон.

Каждый законченный ответ записывается в SQLite под `.local-data/quality/`. Повторный запуск продолжает работу из кеша; изменение модели, промпта, сущности, aliases или полного контекста требует нового ответа. До завершения всех 10 000 комментариев исходные JSON и metadata не меняются. Затем готовятся четыре полных временных файла, проверяются исходные поля и контрольные суммы, выполняется замена; metadata большого набора публикуется последней как указатель на согласованные SHA обоих datasets. Это четыре последовательных atomic replace, а не транзакция файловой системы.

`subset_path` сохраняет прежние 1000 ID и порядок, заменяя комментарии полными объектами из нового набора 10k. Новая стратификация по предсказанным классам не выполняется. Исторические поля текста, контекста и источника не нормализуются; старые `fixture_label` и прежние annotations заменяются новой разметкой.
