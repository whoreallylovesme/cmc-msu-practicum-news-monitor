# Мониторинг Hacker News

Система показывает упоминания выбранной сущности, отношение к ней, динамику,
источники и исходные комментарии. Пользователь работает с дашбордом; запрос,
модели и параметры обработки задаются разработчиком в YAML.

В проекте **шесть микросервисов**: Collector, Storage, ML, Web Master,
Visualization и отдельный Teacher. Первые пять обслуживают мониторинг;
Teacher подключается для новой автоматической разметки.

## Запуск в Docker

Нужны Docker с Compose и Python 3. Команды выполняются из корня проекта:

```sh
cp -n .env.example .env
python3 -m pip install -r demo/requirements.txt
python3 demo/start.py --config demo/1k.yaml
```

Запуск собирает шесть контейнеров, импортирует 1000 готовых комментариев,
обучает ученика, проверяет API и оставляет систему работающей. При первом
обучении скачиваются закреплённые веса нейросетевого ученика, около 0,79 ГБ,
и около 21 МБ дополнительных обучающих CSV.
GGUF-веса учителя для готовой разметки не нужны и не скачиваются.
Интернет нужен для первой установки зависимостей и весов, а также интерфейса
Swagger с CDN. Выгрузка HN уже находится в репозитории.

| Интерфейс | Адрес |
|---|---|
| Дашборд | [localhost:8080](http://127.0.0.1:8080/) |
| Единый Swagger с разделами по микросервисам | [localhost:8080/gateway-docs](http://127.0.0.1:8080/gateway-docs) |
| Web Master | [localhost:8081/docs](http://127.0.0.1:8081/docs) |
| Teacher | [localhost:8082/docs](http://127.0.0.1:8082/docs) |

| Роль | Логин | Пароль |
|---|---|---|
| Администратор: чтение, импорт, обучение и оценка | `admin` | `admin-demo` |
| Читатель: дашборд, комментарии и отчёт | `viewer` | `viewer-demo` |

В Swagger нажмите **Authorize**. Пароли задаются в `.env` или переменных из
[.env.example](.env.example). Порты опубликованы только на этом компьютере.

Для полной выгрузки сначала остановите меньшую версию: стандартные порты общие.

```sh
docker compose -p hn-monitor-demo-1k down
python3 demo/start.py --config demo/10k.yaml
# Остановка полной версии:
docker compose -p hn-monitor-demo-10k down
```

Обычный `down` сохраняет данные и модели в томах. Параметр `with_teacher: false`
в YAML демо оставляет пять основных сервисов; `true` включает шестой профилем
Compose `training`. [Подробности демонстрации и E2E](demo/README.md).

## Работа с результатом

В дашборде можно посмотреть средний балл и число упоминаний, выбрать день или
неделю, нажать на точку графика и прочитать комментарии этого периода, найти
текст и скачать HTML-отчёт. Управления обучением в интерфейсе нет.

| Сервис | Ответственность |
|---|---|
| Collector | Источники, батчи и журнал загрузок |
| Storage | SQLite, поиск FTS5, CRUD комментариев, разметка и оценки |
| ML | Один нейросетевой ученик, обучение, версии, валидация и предсказания |
| Web Master | Авторизация, маршрутизация, импорт, оценка, аналитика и отчёт |
| Visualization | Plotly Dash и общий Swagger |
| Teacher | Разметка отдельной GGUF-моделью через llama.cpp |

У каждого сервиса свои `main.py`, `config.yaml`, `Dockerfile` и HTTP API.
Контракты моделей находятся в разделе **ML** общего Swagger; шлюз пересылает
их через `/services/ml/…`, без повторных ручек моделей в Web Master.

Для нового обучения создайте модель через `POST /services/ml/models` с
`{"entity": "ChatGPT"}`, затем вызовите `POST /services/ml/models/{id}/train`.
Состояние задачи возвращает `GET /services/ml/jobs/{id}`.
`POST /api/score` оценивает сохранённые комментарии закреплённой версией модели;
`GET /api/analytics` и `GET /api/report` возвращают результат.

## Данные и модели

[demo/hn_10k.json](demo/hn_10k.json) содержит 10 000 реальных комментариев HN,
[demo/hn_1k.json](demo/hn_1k.json) — его детерминированное подмножество на 1000.
Сохранены даты, ссылки, заголовки, родительский контекст и готовые метки.
Происхождение и контрольные суммы: [10k](demo/hn_10k.metadata.json),
[1k](demo/hn_1k.metadata.json). Загрузчик проверяет полный вход каждой метки,
включая сущность, алиасы, ID и контекст.

Ученик — **NLI-предобученный ModernBERT-large**: около 398 млн параметров
с адаптерами, из них обучаются 2,43 млн. База закреплена в YAML по URL и SHA-256.
LoRA и голова на шесть классов обучаются на распределениях учителя для HN
и человеческих примерах: 6322 NewsMTSC, 8192 Weather и 1024 Airline.
Полный запуск использует 8023 обучающих комментария HN и 15 538 дополнительных
примера; ещё 1977 HN из отдельных тредов оставлены для проверки.
Происхождение NewsMTSC — в [метаданных](demo/newsmtsc_train.metadata.yaml),
остальных источников — в [описании выборок](demo/training_sources.yaml).
Новые CSV скачиваются с проверкой размера и SHA в локальный кэш.
В репозитории хранятся их URL и выбранные ID/группы; исходные тексты остаются
локально согласно указанным условиям источников.
Вход содержит сущность, алиасы, комментарий и контекст.
Модель совместно оценивает отношение и релевантность: A–E — от сильно
отрицательного до сильно положительного отношения к сущности, F — не по теме.
Отдельного фильтра упоминаний перед моделью нет. На внутренней шкале 0–5
A–E соответствуют 0; 1,25; 2,5; 3,75; 5; у F балла нет.
Человеческие оценки обучают объединённые классы A+B, C, D+E и F;
неопределённая доля ответов разметчиков уменьшает вклад примера в loss.
В Weather по 2048 примеров каждого класса, выбранных по исходной человеческой
разметке. Балансировка меняет состав обучения; мягкие голоса сохраняются.
Градации интенсивности из этих данных не придумываются. Число параметров,
один проход модели и правило релевантности `P(F) < 0.5` сохранены.

Источника обучения два: `dataset` использует сохранённую разметку,
`service` получает распределения шести меток от Teacher. `from_scratch`
обучает новые адаптеры и голову поверх закреплённой базы; `incremental` дообучает на новых или изменённых примерах
с повторением части прежних. Без изменений задача возвращает `skipped`.
При смене состава дополнительных обучающих данных нужен `from_scratch`.
Треды обучения и проверки разделены; версии и адаптеры хранятся в SQLite с SHA-256.

Teacher запускает собственный `llama-server` только при первом запросе разметки.
Одна GGUF-модель сначала составляет короткое объяснение, затем оценивает
вероятности всех шести меток на том же контексте. Параллельные слоты используют
общие веса; отдельные копии модели не запускаются.
Веса, URL либо локальный путь, SHA-256 и параметры CPU/GPU задаются в
[runtime/teacher/config.yaml](runtime/teacher/config.yaml). Код не привязан
к семейству модели. Docker собирает CPU-версию llama.cpp **b12192** из официальных
исходников. Для GPU нужен нативный GPU-бинарник либо внешний `llama.url`;
изменение `gpu_layers` само по себе не добавляет GPU в контейнер.
Шесть вероятностей учителя — условные вероятности меток, а не калиброванная
уверенность. [Контракт и запуск Teacher](runtime/teacher/README.md).

Готовые метки HN демонстрируют конвейер и не являются независимым человеческим
эталоном. Согласие ученика с ними или с учителем не означает такую же точность
на новых обсуждениях. [Отдельная проверка качества](demo/quality/README.md)
использует человеческие метки NewsMTSC, Airline Sentiment и Weather Sentiment: три полярности
отношения к цели и проверку off-topic из другого домена. Она не подтверждает
точность на HN или различение пяти уровней интенсивности.

В V3 увеличено покрытие off-topic человеческими примерами Weather. По DEV
выбран второй checkpoint с меньшим learning rate предобученной NLI-проекции.
Он проходит ограничения основного Weather, News, Airline и HN; на DEV полнота
off-topic равна 74,8%, precision — 76,6%. Единственный провал первоначального
строгого отбора — тональность прежнего Weather: 78,3% против 85,1%.
Этот компромисс принят явно в пользу релевантности, до проверки нового FINAL.
Исходные результаты и проваленный критерий сохранены.

Проверка зафиксированной V3 на новом FINAL ещё выполняется. Таблица ниже
описывает ранее опубликованную V2, а не результат новой модели. Прежние TEST
и FINAL V2 уже просмотрены; новая выборка V3 отложена до обучения.

| Набор | Примеров для полярности | Accuracy до | Accuracy после | Macro-F1 после |
|---|---:|---:|---:|---:|
| NewsMTSC RW, повторно | 803 | 85,3% | 83,6% | 83,3% |
| NewsMTSC MT, повторно | 1034 | 86,2% | 83,3% | 82,0% |
| Airline, повторно | 1000 | 74,5% | 78,3% | 77,4% |
| Weather, повторно | 605 из 792 | 52,9% | 85,0% | 85,5% |
| Weather FINAL V2 | 750 из 1000 | 54,5% | 82,5% | 82,4% |

RW и MT пересекаются, поэтому результаты не объединяются. Улучшение Weather
и Airline сопровождается снижением accuracy NewsMTSC на 1,7–2,9 п.п.
У V2 на её FINAL совместный macro-F1 четырёх
классов равен 62,2%, полнота обнаружения off-topic — 18,0%. На прежнем Weather
эта полнота — 63,6%. Новая выборка сбалансирована по четырём классам и не
представляет частоты настроений всей аудитории. Эти результаты не используются
для дальнейшей настройки текущей версии. На HN независимого человеческого
эталона по-прежнему нет.

Обучение проверено на **одной RTX A6000**: float32, батч 4, контекст до 512
токенов, LoRA-r8, 4 потока CPU. Выбранные две эпохи на 23 561 примере заняли
около 23 минут; в доступных снимках наш GPU-процесс занимал около
7,8 ГиБ при лимите аллокатора 16 ГиБ. Это замер на конкретном сервере,
не измерение пика памяти.
Число параметров осталось 398 269 452, обучаемых — 2 432 006.
Веса адаптеров и головы занимают 9,73 МБ, базовые веса — 0,79 ГБ.
Для запуска нужны база и артефакт с адаптерами и метаданными.
GGUF учителя занимает 4,28 ГБ. В демо с готовыми метками он не загружается.

## Конфигурация и расширение

Основные настройки находятся в [config.yaml](config.yaml):

```yaml
monitoring:
  query: ChatGPT
  aliases: [Chat GPT]
  source: hacker_news
pipeline:
  model_id: null
  teacher: dataset
  training_limit: 10000
offline_demo: true
path_to_offline_demo_data: demo/hn_1k.json
```

`offline_demo: true` использует готовый снимок HN, `false` — живой источник.
Для живого HN задайте вместе `offline_demo: false`,
`monitoring.source: hacker_news`, `pipeline.teacher: service` и запустите
Teacher профилем Compose `training`. Готовые метки `dataset` относятся только к снимку.
`pipeline.model_id` закрепляет модель дашборда; без него выбирается последняя
обученная модель сущности. Настройки ученика и его закреплённые веса находятся
в [конфиге ML](runtime/ml/config.yaml). У файлов весов используется формат
`model_weights: {path, is_local, sha256, size_bytes}`; локальный файл проверяется
так же, как скачанный. Для смены базовой модели ученика нужны совместимая
архитектура и её файлы токенизатора и конфигурации.
Для локального GGUF учителя достаточно `path` и `is_local: true`: SHA-256
вычисляется при старте. [Подключение локального файла в Docker](runtime/teacher/README.md).

`score_scale` в [конфиге Web Master](runtime/web_master/config.yaml) меняет
шкалу интерфейса, отчёта и шлюза, например на 0–10. Новый источник наследуется
от `NewsProvider` и возвращает общие `News`/`NewsComment`:
[пример расширения Collector](runtime/collector/README.md).

## Проверки и нативный запуск

```sh
# Повторная проверка уже запущенного демо:
python3 demo/e2e.py --config demo/1k.yaml

# Нативный запуск с Python 3.12:
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python demo/run.py --config demo/1k.yaml
```

При `native.base_port: 8100` Web Master доступен на 8103, дашборд — на 8104,
Teacher — на 8105. Для отдельного нативного E2E задайте `check.url` в копии YAML.
Для GPU-сервера с CUDA 12.8 и Python 3.12 используйте
`pip install -r requirements-gpu.txt`: проверен Torch 2.11.0+cu128;
CPU/Docker и обычный нативный вариант закреплены на Torch 2.15.0.
Перед запуском выберите выделенную GPU через `CUDA_VISIBLE_DEVICES`.
Все параметры команд демонстрации задаются YAML; в командной строке только
`--config`. Для разметки через Teacher нужен `llama-server` b12192 в PATH
либо путь к нему в `llama.binary`; при `dataset` бинарник не запускается.

CI при изменении кода запускает модульные тесты и Docker E2E отдельно для 1k и 10k:
шесть сервисов, полный импорт и обработка сохранённых меток, оценки всех строк,
права, аналитика, отчёт и повторное обучение без изменений. В CI используется
CPU PyTorch и сокращённый бюджет того же ModernBERT-large: контекст 32 токена,
батч 8 и два шага оптимизатора. Это проверка контрактов конвейера,
**не оценка качества модели**.
GGUF-веса Teacher не скачиваются; веса ученика необходимы.

`lib/` содержит общие контракты и работу с файлами моделей, `runtime/` — сервисы,
`ut/` — модульные тесты, `demo/` — данные, запуск, E2E и проверку качества.
[grade.md](grade.md) связывает реализацию с пунктами задания.
Данные работы, скачанные веса, логи и результаты проверок сохраняются в томах
или `.local-data/` и не добавляются в репозиторий.
