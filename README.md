# Hacker News Monitor

Микросервисный мониторинг отношения к выбранной сущности в комментариях Hacker News.
На дашборде видны упоминания, тональность, источники и исходные комментарии.

Демо использует готовую размеченную выгрузку HN и небольшой TF-IDF-классификатор.
Учитель, трансформеры и скачивание их весов для этого запуска не нужны.
Дополнительный NLI-классификатор и отдельный сервис учителя включаются явно.

## Запуск демо

Нужны Docker, Compose и Python 3 для запуска демонстрационного клиента:

```sh
python3 demo/start.py --dataset 1k
```

Команда собирает пять контейнеров, дожидается готовности и выполняет E2E.
Для полной выгрузки используйте `python3 demo/start.py --dataset 10k`.
Размеры используют отдельные тома; перед переключением остановите прежний проект
либо задайте другие внешние порты.
Сборка устанавливает Python-зависимости, но не скачивает большие ML-веса.
Выгрузка позволяет повторить показ независимо от доступности HN API.
Swagger использует стандартный CDN FastAPI; интернет для интерфейса документации допустим.

- [Дашборд](http://127.0.0.1:8080/)
- [Единый Swagger](http://127.0.0.1:8080/gateway-docs): выбор Web Master или схем внутренних сервисов.
- Администратор: `admin / admin-demo`; читатель: `viewer / viewer-demo`.

Порты привязаны к loopback. Свои порты и пароли задаются через `.env.example`
и переменные окружения; CLI и Compose должны получать одинаковые учётные данные.

Повторить проверку, сравнить два небольших классификатора или остановить демо:

```sh
python3 demo/e2e.py --dataset 1k --compare
docker compose -p hn-monitor-demo-1k down
```

Состояние хранится в именованных томах. Обычный `down` их не удаляет.
Подробности запуска находятся в [demo/README.md](demo/README.md).

## Пользовательские сценарии

1. Загрузить комментарии по сущности: из готового снимка или живого HN API.
2. Создать классификатор, обучить с нуля или дообучить на новых размеченных данных.
3. Оценить собранные комментарии и новые тексты через API.
4. Исследовать динамику, открыть комментарии выбранного периода и скачать HTML-отчёт.

Администратор может загружать данные, создавать, обучать и применять модели.
Читатель просматривает графики, комментарии и отчёты; операции записи возвращают 403.

## Архитектура

| Сервис | Назначение и основные API |
|---|---|
| `runtime/collector` | Источники, `/batch`, `/loads`; батчи и журнал загрузок |
| `runtime/storage` | SQLite и FTS5; CRUD `/comments`, записи `/labels` и `/predictions` |
| `runtime/ml` | `/models`, `/train`, `/predict`, `/validate`, `/summary`, `/jobs`; обучение и версии |
| `runtime/web_master` | Единая точка входа `/api/*`, HTTP Basic, роли и сценарии |
| `runtime/visualization` | Plotly Dash, выбор периода, поиск, отчёт и Swagger |
| `runtime/teacher` | Необязательный `/label` для новой автоматической разметки |

Каждый сервис имеет `main.py`, `config.yaml`, `Dockerfile` и `requirements.txt`.
Общие типы, загрузка конфигов, HTTP-клиент и поиск упоминаний находятся в `lib`.
Новый источник наследуется от `NewsProvider` и возвращает `News` / `NewsComment`;
пример подключения описан в [runtime/collector/README.md](runtime/collector/README.md).

## Данные и готовая разметка

В `demo/` находятся две размеченные выгрузки настоящих комментариев:

- [hn_10k.json](demo/hn_10k.json): 10 000 комментариев из 60 тредов про ChatGPT.
- [hn_1k.json](demo/hn_1k.json): 1000 строк, строгое подмножество полной версии.

Малая версия отобрана детерминированно по классам с сохранением их пропорций.
Одинаковые ID имеют одинаковые исходные данные и метки в обеих версиях.
Сохранены даты, заголовки, контекст и ссылки на оригиналы. Происхождение,
распределение меток и SHA-256: [10k](demo/hn_10k.metadata.json),
[1k](demo/hn_1k.metadata.json).
Это целевая выборка, а не репрезентативная перепись аудитории HN.

Каждый комментарий имеет `label`, `label_entity`, `label_source` и `label_fingerprint`:

| Класс | Смысл | Балл по умолчанию |
|---|---|---:|
| A | Отрицательно | 0 |
| B | Скорее отрицательно | 1,25 |
| C | Нейтрально | 2,5 |
| D | Скорее положительно | 3,75 |
| E | Положительно | 5 |
| F | Не относится к сущности | Балл не присваивается |

Источники меток — отдельная проверка ассистентом, правила отсутствия упоминания
и заранее рассчитанные предсказания Base. Точные количества указаны в метаданных
каждой версии и в `label_source`. Это подготовленная разметка для показа конвейера,
не независимый человеческий gold. Проверка по ней измеряет согласие с метками.

Loader сверяет сущность и отпечаток полного контекста. После редактирования
текста метку нужно обновить; изменившиеся данные нельзя незаметно обучить
на устаревшей разметке. Учитель `dataset` читает метки из того же файла,
который использует Collector; нейросеть при этом не запускается.

Для новой выгрузки: `python runtime/collector/fetch_snapshot.py`.
Она сохраняется в `.local-data/hn_snapshot.raw.json` и не заменяет размеченное демо.

## Конфигурация

[config.yaml](config.yaml) задаёт сущность, алиасы, источник и правила упоминаний:

```yaml
monitoring:
  query: ChatGPT
  aliases: [Chat GPT]
  source: hacker_news
  matching:
    allow_typos: true
    allow_context: true
    context_hints: []
offline_demo: true
path_to_offline_demo_data: demo/hn_1k.json
```

`offline_demo` переключает только Collector на снимок. Для живого сбора задайте
`false`; новые тексты можно оценивать обученной моделью. Для их обучения нужны
метки: подготовленные, проверенные или полученные от отдельного учителя.
После смены сущности подготовьте соответствующую разметку.

Поиск учитывает прямое имя, алиасы, одну опечатку и простую отсылку из ближайшего
контекста. Один заголовок не делает всю ветку упоминанием. Один комментарий
учитывается один раз.

Адреса сервисов, ограничения и таймауты находятся в их YAML-конфигах.
`score_scale: {min: 0, max: 10}` в конфиге Web Master меняет публичные баллы,
график и отчёт; исходные вероятности сохраняются отдельно.

## Обучение и модели

По умолчанию `hard_label`: TF-IDF по словам и символьным n-граммам, линейный
классификатор. Вариант `softmax` учится на распределении меток, `tiny_mlp`
добавляет небольшой скрытый слой. Эти режимы работают без больших весов.
Тональность оценивается относительно выбранной сущности; вне области упоминания
модель возвращает F.

`from_scratch` создаёт новую версию. `incremental` использует новые или изменённые
примеры и повтор прежних; если изменений нет, возвращается `skipped`.
Треды обучения и проверки не пересекаются и сохраняют роли между версиями.
Артефакты и метаданные версий хранятся в SQLite с проверкой SHA-256.

Доступные источники обучения: `dataset`, `reviewed`, `service`, а также
дополнительные `fixture`, `snapshot`, `live`. Для демо используется `dataset`.
Отдельные проверенные метки находятся в `runtime/ml/reviewed_training_labels.json`.

Для явного NLI-режима выберите `kind: semantic`. Его замороженная DeBERTa Base
и 54 обучаемых коэффициента требуют больших весов. URL, SHA и токенизатор
задаются в `student_encoder` конфигурации ML. Модель скачивается по запросу;
кэш хранится отдельно от исходников. Для её предварительной подготовки:

```sh
python runtime/ml/prepare.py
```

На прежней отдельной ассистентской проверке NLI-вариант получил 62,6% точности
полярности; цель 70% не подтверждена. Это не оценка лёгкого демо-классификатора.
Контрольный корпус и метки находятся в `runtime/ml/evaluation_corpus.json`
и `runtime/ml/evaluation.json`.

## Дополнительный учитель

```sh
python3 demo/start.py --with-teacher
```

Профиль `training` добавляет шестой контейнер. Его API и Swagger запускаются
без больших весов; они скачиваются при первом запросе разметки по теме
и сохраняются в отдельном томе. Обычное демо использует готовые метки.
В едином Swagger внутренние схемы доступны для просмотра; запросы выполняются
через публичный API Web Master с HTTP Basic.
Для новой разметки выберите `teacher: service` в API или GUI.
Контракт, проверка ревизий и кэш описаны в [runtime/teacher/README.md](runtime/teacher/README.md).

Веса учителя задаются в `runtime/teacher/config.yaml`, NLI-классификатора —
в `runtime/ml/config.yaml`. В обоих случаях используется общий формат:

```yaml
model_weights:
  path: https://huggingface.co/owner/model/resolve/revision/model.onnx
  is_local: false
```

Для локального файла укажите путь и `is_local: true`, согласовав SHA-256,
токенизатор и формат выходов. Дополнительный GGUF-режим `live` использует
параметры `model_weights` и `llama_*` в ML-конфиге; Docker-target `with-llama`
выбирается через `ML_IMAGE_TARGET=with-llama`. При обычном запуске он не собирается.

## Нативный запуск

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python demo/run.py
```

В другом терминале: `python demo/e2e.py --dataset 1k --url http://127.0.0.1:8103`.
Дашборд работает на 8104. `--with-teacher` у launcher добавляет учителя на 8105;
его веса можно подготовить через `python runtime/teacher/prepare.py`.

Ежедневный цикл: `python runtime/web_master/daily.py --model-id <id>`.
Используйте готовую разметку только для строк, которым она соответствует;
для новых неразмеченных комментариев подключайте `service` или обновляйте метки.

## CI и оценка задания

GitHub Actions матрицей проверяет обе версии: 1k и 10k. В каждом задании
запускаются пять контейнеров и тот же `demo/e2e.py`, что используется на защите. Проверки падают при ошибках импорта, обучения, предсказаний, отчёта
или прав. Большие модели для этого сценария не загружаются.
Результаты прогонов и скриншоты не сохраняются в репозиторий.

Соответствие каждому критерию задания и ожидаемые баллы: [grade.md](grade.md).
