# Сервис учителя на ONNX

Teacher размечает комментарии для обучения. Он работает отдельно от малого
классификатора и не импортирует код сервиса ML, PyTorch, GGUF или llama.cpp.
В исходном конфиге закреплена большая NLI-модель. Её оценки — экспериментальная
автоматическая разметка, а не независимый человеческий эталон.

В проекте пять основных сервисов и дополнительный Teacher. Конфиг
`demo/1k.yaml` запускает все шесть. Обучение с источником `dataset` и применение
готового классификатора не обращаются к Teacher. Для разметки через него
нужно выбрать источник `service`. В `/api/status` Web Master проверяет
пять основных сервисов; Teacher в эти обязательные проверки не входит.

Основная модель — небольшой TF-IDF-классификатор, обучаемый на готовом датасете.
Он не загружает нейросетевой энкодер и не вызывает Teacher. Дополнительный режим
`semantic` использует замороженную NLI-модель Base и 54 обучаемых коэффициента,
а Teacher — отдельно настроенную модель Large. Доступность Teacher сама по себе
не подтверждает качество его разметки.

## Запуск вместе с мониторингом

```sh
python3 demo/start.py --config demo/1k.yaml
```

Команда включает профиль `training`. Демо по-прежнему обучается на готовых
метках `dataset` и не запрашивает новую нейросетевую разметку. Swagger Teacher:
[localhost:8082/docs](http://127.0.0.1:8082/docs). Параметр `ports.teacher`
в YAML демо меняет локальный порт; внутри Docker ML обращается к
`http://teacher:8000`.

При сборке образа устанавливаются зависимости, но не скачиваются веса модели
и токенизатор общим размером около 1,75 ГБ. `/health`, `/metadata` и `/docs`
работают без загрузки нейросети. Первый `POST /label` с упоминанием нужной темы
скачивает и проверяет файлы в постоянном томе `teacher-encoder-weights`.
Для предварительной загрузки после запуска Teacher:

```sh
docker compose -p hn-monitor-demo-1k --profile training exec teacher python prepare.py
```

Для обучения через Teacher создайте модель запросом `POST /services/ml/models`
в общем Swagger, затем вызовите `POST /services/ml/models/{id}/train` с телом
`{"teacher": "service", "mode": "from_scratch", "limit": 100}`.
Состояние задачи возвращает `GET /services/ml/jobs/{id}`. Для выбранной сущности
должны быть загружены комментарии как минимум из двух тредов.

При нативном запуске задайте доступный для записи каталог кэша:

```sh
export TEACHER_ENCODER_CACHE_DIR="$PWD/.local-data/teacher/encoder-weights"
python demo/run.py --config demo/1k.yaml
```

При базовом порте 8100 Swagger Teacher доступен на 8105, а Web Master — на 8103.
Параметр `native.base_port` в YAML сдвигает все порты вместе.
При `with_teacher: false` запускаются только пять основных сервисов.
Остановка Teacher не останавливает их процессы.

## REST API и кэш разметки

`/health` сообщает состояние сервиса и загружена ли модель. Ответ 200 до её
загрузки — нормальное поведение. `/metadata` возвращает версию, контрольные
суммы файлов и точный формат входа и выхода без загрузки нейросети.

`POST /label` принимает `entity`, необязательные `aliases` и `matching`,
а также от 1 до 100 комментариев в `items`. У каждого комментария есть
`id`, `story_id`, `text` и необязательные `story_title`, `parent_text`, `parent_id`.
Для `story_title` и `parent_text` также принимаются алиасы `title`/`parent`.
Формат ответа: `{revision, items: [{comment_id, probabilities, input_hash}]}`.
Шесть конечных неотрицательных вероятностей в сумме дают единицу и соответствуют
классам A/B/C/D/E/F из `lib.sentiment`. Балл рассчитывает вызывающая сторона.
Для комментария без подходящего упоминания возвращается F с вероятностью 1;
модель для этого не загружается.

Клиенты используют `input_hash` (также доступен как `teacher_input_hash`)
из `lib.teacher_contracts`. Хеш включает полный исходный текст и контекст,
сущность, её алиасы и действующие правила поиска упоминаний. Версия определяется
хешами закреплённых файлов модели и токенизатора, а также форматом адаптера.
Изменение этих данных меняет версию; путь к каталогу кэша на неё не влияет.

`runtime/ml/teacher_client.py` сначала закрепляет `/metadata` для задачи обучения,
затем отправляет запросы батчами. Storage кэширует метки по ключу
`entity + service-<revision> + comment_id`. Запись используется повторно только
при совпадении полного хеша входа. Дублирующиеся, пропущенные и посторонние ID,
неверные хеши и несовпадение версии ответа отклоняются. Новая версия учителя
обновляет метки для дообучения, сохраняя разделение тредов на обучение и проверку.
Отдельные ручные корректировки поверх выбранного источника меток не применяются.

Некорректное тело запроса возвращает 422; недоступные или повреждённые файлы
модели и ошибки инференса — 503. Если Teacher недоступен, явно запрошенное
обучение с источником `service` завершается ошибкой, сохраняя предыдущую готовую
модель. Предсказание малого классификатора никогда не вызывает Teacher.
Инференс и отложенная инициализация защищены блокировками; ONNX Runtime
по умолчанию использует два потока CPU.

## Замена модели

Для замены модели Hugging Face измените YAML или укажите другой файл
через `TEACHER_CONFIG`:

- Задайте `model_weights` и `tokenizer` в формате `{path, is_local, sha256}`.
  Необязательный `size_bytes` включает проверку размера файла. Относительные
  локальные пути считаются от каталога конфига. Поддерживаются только ONNX-модели
  без отдельных файлов внешних весов.
- При `backend: sequence_classifier` задайте порядок классов исходной модели
  через `class_mapping`, например `[B, C, D]` для отрицательной, нейтральной
  и положительной тональности. Несколько исходных классов могут соответствовать
  одному классу A–F; их вероятности суммируются.
- Для парного входа используется `sequence: {input_format: pair, text_template: '{text}',
  target_template: '{entity}'}`. Если модель требует явного разделителя,
  задайте `input_format: text` и шаблон, например `'{text} </s> {entity}'`.
- Для NLI задаются `nli.premise_template`, три гипотезы `nli.hypotheses`
  с нужной сущностью и `entailment_index`. Три исходных логита следования
  нормализуются через softmax и сопоставляются классам через `class_mapping`.
  В метаданных они обозначены как некалиброванные `hypothesis_scores_softmax`,
  а не как калиброванная уверенность модели.
- Согласуйте `pad_token_id`, `pad_token` токенизатора и `max_length` модели.

В шаблонах доступны `{entity}`, `{text}`, `{story_title}`, `{parent_text}`
и алиасы `{title}`/`{parent}`. По умолчанию NLI оценивает тональность только
текущего комментария; родительский комментарий и заголовок используются
для определения упоминания.

Dockerfile создаёт доступный для записи кэш с UID/GID 10001 и запускает сервис
без прав root. Compose сохраняет скачанные файлы в `teacher-encoder-weights`.
Имена файлов определяются SHA-256; перед использованием файлы проверяются,
а `lib/model_assets.py` устанавливает их атомарно. Каталог кэша задаётся
через `TEACHER_ENCODER_CACHE_DIR`; для предварительной загрузки его можно
переопределить параметром `prepare.py --cache-dir`. После загрузки файлов
сеть для работы модели не нужна. При смене закреплённых весов в YAML заранее
скачайте соответствующие файлы перед офлайн-запуском. Нативная предварительная
загрузка выполняется командой `python runtime/teacher/prepare.py`
с той же переменной окружения для кэша.
