# Учитель тональности

Teacher получает сущность, её алиасы, комментарий, родительский комментарий и
заголовок треда. Одна GGUF-модель совместно выбирает A–E (от сильно отрицательного
до сильно положительного отношения к сущности) или F (не по теме). Регулярные
выражения и отдельный фильтр упоминаний не участвуют в разметке.
Шесть вероятностей — сохранённый формат разметки учителя.
Текущий ученик объединяет A+B, C и D+E в три тона и отдельно учит
релевантность по F. Его скалярная оценка имеет фиксированную шкалу 0–1.

```sh
python runtime/teacher/main.py --config runtime/teacher/config.yaml
```

Swagger: [localhost:8082/docs](http://127.0.0.1:8082/docs). Доступны `GET /health`,
`GET /metadata`, `POST /label`. Метаданные и Swagger работают без загрузки весов.
Первый запрос разметки проверяет или скачивает модель и запускает локальный
`llama-server`. Завершение Teacher останавливает только запущенный им процесс.
Нативный запуск не требует Docker.

В `config.yaml` задаются `model_weights: {path, is_local, sha256, size_bytes}`:
путь может быть HTTPS URL Hugging Face либо локальным файлом. Для локального
файла достаточно `path` и `is_local: true`: если SHA-256 не указан, при старте
сервис проверяет размер и вычисляет отпечаток файла. Замена содержимого меняет
revision и кэш разметки. Для удалённого файла SHA-256 обязателен; загрузка остаётся
отложенной. Относительный локальный путь считается от каталога YAML. Имя модели в коде не
закреплено; другая модель должна поддерживать chat template и отдельные токены
A–F. Выбранная GGUF-модель Q8_0, её ревизия и SHA-256 указаны в поставляемом YAML.
Vision projector для текстовой разметки не нужен.

Для файла на компьютере сначала укажите в `runtime/teacher/config.yaml`:

```yaml
model_weights:
  path: /local-model/teacher.gguf
  is_local: true
```

Затем подключите файл через overlay Compose:

```sh
MODEL_LOCAL_PATH=/absolute/path/model.gguf \
docker compose -p hn-monitor-demo-1k \
  -f docker-compose.yml -f docker-compose.local-model.yml \
  --profile training up --build --wait
```

`MODEL_LOCAL_PATH` задаёт только файл для bind mount. Выбор локальных весов
определяется YAML; дополнительного переключателя модели в окружении нет.

Параметры `llama` задают бинарный файл, потоки CPU, контекст, GPU layers,
параллелизм и timeout. `context_size` — лимит одного запроса; общий контекст
сервера умножается на `parallel`. Поставляемый Docker-образ работает на CPU:
`gpu_layers` не добавляет ему поддержку CUDA или Metal. Для GPU нужен нативный
бинарник b12192 с поддержкой вашего GPU; на macOS с Metal можно задать
`gpu_layers: -1`. Другой вариант — внешний GPU-сервер в `llama.url`. Если URL задан, Teacher
обращается к готовому серверу и не скачивает веса, не запускает и не останавливает
его. Внешний сервер должен обслуживать указанные в конфиге веса и быть запущен
с `--alias`, равным их SHA-256: Teacher проверяет эту идентичность через `/v1/models`.

Контракт llama.cpp закреплён за b12192. Перед инференсом Teacher проверяет
токенизацию меток и ограничивает текущий комментарий 2048, родителя 512,
заголовок 128 токенами модели; лимиты настраиваются. Полный сформированный
prompt также проверяется на размер контекста. Хеш входа сохраняет полный
исходный текст, включая отброшенную часть.

Выход — нормированные вероятности следующего токена, условные на шести допустимых
метках и сгенерированном объяснении. Сначала модель коротко описывает основания
оценки, затем на том же контексте вычисляются шесть оценок классов. Режим один:
отдельного переключателя быстрого ответа без объяснения нет. Шаблон задан в
`system_prompt`; `evidence_generation` задаёт бюджет 96 токенов, температуру 0
и просьбу уложиться в 30 слов. Сервис требует завершённый раздел `CLASS:` и
непустое объяснение; превышение желаемого числа слов само по себе не ошибка.
Оборванный ответ не превращается в метку. При уровне DEBUG объяснение попадает
в журнал, но не меняет контракт API и интерфейс пользователя.

После объяснения первый короткий запрос возвращает исходные log probabilities
для top-64 токенов и выбранной буквы. Для отсутствующих меток выполняются
дополнительные запросы с той же кэшируемой подсказкой: грамматика фиксирует
выходную букву, а сервер возвращает её исходную log probability до ограничений.
Если все метки есть в первом ответе, достаточно одного запроса оценки классов. Шесть значений нормализуются вместе;
пропущенные значения не заменяются искусственными оценками. Это обходит
особенность b12192: список top probabilities после sampling не всегда ограничен
грамматикой. Оценки получены из модели, но не являются калиброванной уверенностью в
правильном ответе. Метаданные содержат prompt, правила усечения, параметры вывода
и контрольную сумму весов. Их изменение меняет revision и инвалидирует старый кэш.

Объяснение увеличивает стоимость разметки: в локальных прогонах на Mac короткий
комментарий занимал примерно 1–2 секунды. Это ориентир, а не гарантия скорости;
время зависит от модели, длины текста и CPU/GPU. Предсказание ученика не вызывает Teacher.

Кэш: `TEACHER_MODEL_CACHE_DIR` или `cache_dir`; логи дочернего llama.cpp:
`TEACHER_LOG_DIR` или `log_dir`. По умолчанию это каталоги `.local-data` в корне
проекта. Docker-образ включает CPU-бинарник, собранный из официального
llama.cpp b12192; тот же образ умеет обращаться к внешнему серверу. Веса
не входят в образ. Ошибки загрузки и инференса логируются, `/label` отвечает 503.
